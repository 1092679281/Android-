# R18 · 别克君越 E2LB 无线 CarPlay 身份同步

## 15:27 实车日志与 15:29 截图

- 上汽通用 E2LB 的一条 RFCOMM 链路完成了 iAP2 协商，另一路协商超时。成功的链路发送了 `0x4300`，所贴日志窗口内未见车机发回已声明支持的 `0x4301`。
- 15:27 的广播和蓝牙日志记录了占位地址。15:29 设置页显示已保存手动地址，这个状态无法证明更早发出的报文使用了该地址。
- 截图中的 `pair-verify` 已完成，失败点在初始 AirPlay `SETUP`。截图未显示这次拒绝的响应码或端点来源。此前的 R16 实车报告记录过网关猜测端点上的 500，判断这次是否相同需查看本轮报告。
- iAP2 的 `0xaa05` 发送时，认证状态仍是 `RESPONSE_UNVERIFIED`。这条记录无法确认车机的 CarPlay 授权状态。

## 16:16 自动连接复测

- 日志出现了 `IDENTITY: 本轮固定地址`，确认已运行身份同步版。`source=未获取 placeholder=true` 表明本轮启动时无可用的手机蓝牙地址。随后识别出 E2LB，所贴日志里 `wifiSource=NONE startSession=false`，尚未进入 AirPlay SETUP。
- `AUTO: 已读取快捷连接声音选择` 出自蓝牙触发的后台连接。此前这个入口直接启动控制广播和 RFCOMM，绕过了首页的身份提示。

## 本次修复

- 在后台解析本机经典蓝牙地址，然后启动 ctrl 广播及主动、被动 RFCOMM。三条路径共用本轮固定地址，AirPlay `SETUP` 的 `deviceID` 沿用同一地址。取消连接时作废尚未完成的解析任务。
- 自动连接和首页连接共用蓝牙身份检查。未读到地址时，界面与报告显示 `BT_IDENTITY_REQUIRED`，真车连接停在准备阶段。测试台可显式选用占位地址。
- 从「启动连接」进入时，应用先尝试读取；需要手填时，保存一次即可继续。后续自动连接会复用保存地址。连接期间修改地址，界面会说明重新发起连接后生效。
- iAP2 的 Phase 1 日志直接记录热点来源、是否收到 `0x4301`、是否有车机提供的 AirPlay 端口。
- 回归测试覆盖已知蓝牙地址和占位地址传入 AirPlay 后的 `deviceID` 取值。此前 R16 的 SETUP 响应码和端点诊断继续用于实车复测。

## 实车复测

重新发起连接后，先在日志核对 `IDENTITY: 本轮固定地址` 是否显示 `placeholder=false`。如仍失败，导出同一轮的脱敏诊断，保留 `0x4301`、ctrl 邀请、AirPlay 端点来源和 `SETUP 应答`。先确认会话级 SETUP 有效、屏幕流 SETUP 和 RECORD 完成，再核对车机出画。

GitHub Actions 产出的是 Debug 测试包，覆盖安装取决于两版 APK 的签名是否相同。
